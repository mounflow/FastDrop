# FastDrop 应用直达设计

**日期：** 2026-08-15

**状态：** 设计章节已确认，等待文档终审

**首版平台：** Android 手机 → Windows 电脑

## 1. 背景与目标

FastDrop 已能在局域网内完成手机与电脑之间的可恢复文件传输。本功能在现有传输之上增加一个可选的“应用直达”能力：手机发送照片时，可选择电脑当前已打开的受支持应用或网页，文件在电脑上完整保存后，FastDrop 将图片放入目标输入区。

首版正式支持：

- Windows 微信当前会话；
- Chrome 和 Edge 中的 Gemini 标签页；
- 单张和多张图片。

该功能只将图片放入输入区，绝不模拟回车，也不点击“发送”或“提交”。用户在目标应用中检查内容后自行发送。

## 2. 产品边界

“应用直达”是附加功能，不改变 FastDrop 的默认传输体验。

- 电脑端功能总开关默认关闭；
- 电脑端按已配对设备单独授权，可随时撤销；
- 手机端“应用直达”设置默认关闭；
- 功能启用后，每次发送仍需主动点击“发送到电脑应用”；
- 未使用应用直达时，手机不请求电脑窗口或标签页列表；
- 文件传输和应用投递是两个独立结果，投递失败不会将已保存的文件标记为传输失败。

首版不包含：

- 自动点击发送；
- 从手机上选择微信联系人或读取聊天列表；
- 向管理员权限窗口或 Windows 安全界面投递；
- 默认枚举并展示所有软件和网页；
- 公网远程投递；
- 普通文件的应用投递。协议和数据模型可预留文件类型，但首版 UI 只开放图片。

## 3. 总体架构

现有 HTTP 文件通道、WebSocket 控制通道和传输状态机保持不变。新能力在电脑侧增加一层独立的投递编排。

### 3.1 手机端

新增独立的 `app_delivery` 功能模块，负责：

- 检查目标电脑的能力与当前设备权限；
- 在用户主动进入时获取可投递目标；
- 按电脑设备分组展示应用和网页；
- 向现有传输请求附加可选的 `deliveryIntent`；
- 显示与文件传输状态分离的投递状态；
- 对已保存文件发起“重新投递”，不重复上传。

### 3.2 Windows 桌面端

在 Go 服务中新增 `internal/delivery/` 边界，核心组件为：

- `TargetRegistry`：汇总受支持应用和浏览器扩展提供的当前目标；
- `PermissionService`：检查功能总开关和已配对设备授权；
- `DeliveryCoordinator`：在传输完成后创建投递任务，执行排队、重试和状态推送；
- `TargetResolver`：在粘贴前重新校验目标身份和可用性；
- `ClipboardService`：备份常见剪贴板格式、写入图片并按结果恢复；
- `AdapterRegistry`：管理微信、Gemini 和实验性通用适配器。

文件完成 SHA-256 验证、原子重命名并写入最终路径后，`DeliveryCoordinator` 才可开始投递。

### 3.3 浏览器扩展

提供 Chrome/Edge Manifest V3 扩展，建议放置在独立目录 `fastdrop-browser-extension/`。扩展只负责：

- 查找受支持站点的标签页；
- 将用户选择的标签页激活并将浏览器窗口置于前台；
- 在已获得站点权限的正式适配器中，聚焦图片可粘贴区域；
- 向本机 FastDrop 服务回传目标就绪或失败状态。

扩展不负责上传文件，不读取对话正文或输入内容，不执行发送。正式版 Gemini 适配器只申请 `gemini.google.com` 必要的站点权限。

## 4. 支持列表与目标发现

### 4.1 适配器注册表

每个适配器定义：

- 稳定的 `adapterId`；
- 目标类型：原生窗口或浏览器标签页；
- 可信的进程、签名或域名匹配规则；
- 可用的窗口类型或页面规则；
- 单图、多图和剪贴板格式能力；
- 激活、聚焦、粘贴和就绪检查策略；
- 验证过的应用版本范围；
- 状态：稳定、实验性或禁用。

默认注册的稳定适配器为：

- `wechat.windows`：目标为微信当前可见主窗口；
- `gemini.web`：目标为 Chrome/Edge 中匹配 Gemini 域名的标签页。

Chrome 和 Edge 是 Gemini 适配器的载体，不会因为浏览器受支持就将其他标签页全部上报。

### 4.2 默认发现规则

默认模式不收集通用应用清单。Windows 侧只对顶层窗口读取匹配支持列表所需的最小进程身份信息，仅在匹配正式适配器后读取目标显示信息。浏览器扩展只查询支持站点的 URL 匹配模式。

手机只能看到同时满足以下条件的目标：

1. 电脑功能总开关已启用；
2. 当前配对设备已获授权；
3. 对应适配器已启用且通过健康检查；
4. 目标当前存在且可交互；
5. 目标不是系统窗口、密码界面、锁屏界面或高权限窗口。

### 4.3 实验性通用投递

电脑设置提供默认关闭的“实验性通用投递”开关。开启后才枚举其他可见窗口和网页，并在手机端明确标记“实验性”。通用适配器只承诺尝试激活和粘贴；不能确认目标已接收时，降级为手动粘贴。

## 5. 用户流程

### 5.1 首次启用

1. 用户在电脑 FastDrop 设置中开启“应用直达”；
2. 电脑展示隐私说明、已支持应用和浏览器扩展状态；
3. 用户为某个已配对手机开启权限；
4. 用户在手机设置中启用“应用直达”；
5. 若需要 Gemini，电脑端引导安装并连接 FastDrop 浏览器扩展。

### 5.2 发送

1. 手机选择一张或多张照片；
2. 选择一台或多台接收设备；
3. 对 Windows 电脑，用户主动点击“发送到电脑应用”；
4. 手机按电脑分组展示当前可用目标，每台电脑分别选择目标；
5. 文件按现有流程传输、校验和保存；
6. 电脑默认直接执行投递；若“投递前确认”开关已启用，则先由电脑确认；
7. 目标输入区出现图片后，由用户检查并手动发送。

发送给 Android 等非 Windows 设备时，保持原有普通传输，不显示应用目标。

### 5.3 失败与重新投递

目标关闭、身份变化或粘贴失败时：

- 文件传输仍保持 `completed`；
- 手机与电脑分别显示投递失败原因；
- 剪贴板保留待投递图片，提示用户手动按 `Ctrl+V`；
- 传输记录提供“重新投递”，重新获取目标并创建投递任务，不重复上传。

## 6. 协议扩展

所有新端点继续使用 `/api/v1/` 前缀，保护端点同时需要 `Authorization: Bearer <sessionToken>` 和 `X-Session-Id`。

### 6.1 能力与目标

- `GET /api/v1/delivery/capabilities`：返回功能开关、当前设备授权、稳定适配器、扩展状态和图片数量能力；
- `GET /api/v1/delivery/targets`：仅对已授权会话返回当前可用目标快照；
- `POST /api/v1/transfers/{transferId}/deliveries`：对已保存传输新建或重新创建投递任务。

目标快照建议模型：

```json
{
  "revision": "opaque-revision",
  "targets": [
    {
      "targetId": "opaque-random-id",
      "kind": "native_app",
      "adapterId": "wechat.windows",
      "appName": "微信",
      "displayName": "微信当前会话",
      "iconKey": "wechat",
      "stability": "stable",
      "capabilities": {"images": true, "multipleImages": true}
    }
  ]
}
```

`targetId` 必须是随机、不透明、与当前已认证设备会话绑定的内存态标识，不得直接编码 PID、HWND、标签页 ID 或 URL。目标关闭、服务重启或会话终止后失效。

### 6.2 传输意图

现有 `POST /api/v1/transfers` 和 `file.offer` 增加可选字段：

```json
{
  "deliveryIntent": {
    "mode": "app",
    "targetId": "opaque-random-id",
    "targetRevision": "opaque-revision"
  }
}
```

不携带 `deliveryIntent` 时，服务端走完全相同的现有传输逻辑。服务端在创建传输时校验权限和目标所属会话，并在实际粘贴前再次解析和校验。

`deliveryIntent` 结构非法时，整个创建请求按 `INVALID_REQUEST` 拒绝。但结构合法的意图如果因功能关闭、授权被撤销、目标过期或扩展断开而无法接受，服务端仍必须创建并完成普通文件传输，不得因附加功能不可用而阻止文件保存。创建响应中单独返回 `delivery.accepted=false` 和脱敏错误码，手机将该结果显示为投递失败或降级为普通传输。

### 6.3 WebSocket 状态

新增 `delivery.status` 消息，负輣与文件传输状态分离的投递进度。不修改现有 `transfer.completed`。

投递主状态：

`pending → waiting_confirm → activating → pasting → delivered`

终止或降级状态：

- `target_unavailable`；
- `manual_paste_required`；
- `cancelled`；
- `failed`。

`delivered` 表示稳定适配器已完成目标校验并派发了粘贴动作，不表示内容已由第三方应用发送。UI 应使用“已放入输入区，请确认后发送”类型文案。

### 6.4 错误模型修订

新功能需向现有闭集错误码词汇正式追加：

- `DELIVERY_DISABLED`；
- `DELIVERY_NOT_AUTHORIZED`；
- `DELIVERY_TARGET_UNAVAILABLE`；
- `DELIVERY_TARGET_CHANGED`；
- `DELIVERY_EXTENSION_UNAVAILABLE`；
- `DELIVERY_FOCUS_DENIED`；
- `DELIVERY_CLIPBOARD_FAILED`；
- `DELIVERY_UNSUPPORTED`。

响应仍使用标准 `{error: {code, message, requestId, details}}` 结构。`details` 不得包含窗口标题、网页标题、完整 URL、PID 或 HWND。

## 7. 投递执行

### 7.1 共通安全顺序

1. 校验投递任务、文件路径和 SHA-256 校验结果；
2. 重新解析 `targetId`，校验适配器、进程身份、窗口或标签页；
3. 检查电脑未锁屏，目标不是高权限或安全界面；
4. 若开启“投递前确认”，等待电脑用户确认；
5. 备份剪贴板中的常见数据格式；
6. 激活目标并确认实际前台目标与选择目标一致；
7. 由目标适配器写入图片剪贴板格式，执行粘贴；
8. 若用户在关键窗口内切换了前台目标，中止后续操作，绝不尝试向新窗口粘贴；
9. 投递成功后恢复原剪贴板；投递失败时保留图片，便于手动粘贴。

剪贴板恢复覆盖 Unicode 文本、HTML、常见图片和文件列表格式。第三方软件的私有、延迟渲染或无法复制格式只能尽力恢复，UI 隐私说明需如实告知。

### 7.2 微信适配器

- 只定位已验证的微信可见主窗口；
- 不读取或展示联系人和会话标题；
- 将目标显示为“微信当前会话”；
- 使用适配器已验证的多图剪贴策略；
- 微信版本超出验证范围或窗口结构校验失败时，不盲目注入，将适配器标记为不可用或实验性。

### 7.3 Gemini 适配器

- 扩展只返回匹配 Gemini 域名且当前可用的标签页；
- 手机可在多个 Gemini 标签页中精确选择；
- 扩展先激活标签页并聚焦支持图片的输入区，再通知桌面端粘贴；
- 页面结构不符合已验证适配器时中止自动粘贴，降级为手动粘贴；
- 扩展不点击发送，不监听用户输入文本。

### 7.4 多图与并发

多张图片对用户表现为一个投递任务。具体是单次批量粘贴还是按图片顺序粘贴，由每个适配器的已验证策略决定。任何情况下都不执行发送动作。

M:N 文件传输继续并行。但同一台 Windows 电脑的投递任务必须进入单一 FIFO 队列串行执行，避免多台手机抢占剪贴板和前台窗口。队列中的目标在真正执行时再次校验。

## 8. 数据存储

在既有五张核心传输表之外，新增独立 `delivery_jobs` 表。该表是新功能的显式协议扩展，不改变传输表和 chunk bitmap 设计。建议字段包含：

- `id`；
- `transfer_id`；
- `requesting_device_id`；
- `adapter_id`；
- `target_kind`；
- `status`；
- `created_at`、`started_at`、`completed_at`；
- `error_code`、`error_message`。

不存储 `targetId`、窗口标题、标签页标题、完整 URL、PID 或 HWND。投递时所需的实时目标映射只存于内存。

在现有 `devices` 表增加 `allow_app_delivery` 布尔字段，默认为 `false`，用于电脑端按设备授权。电脑端功能总开关保存在本地配置中。

服务重启时，所有 session 和内存目标映射按现有约定失效。尚未执行的 `delivery_jobs` 必须标记为 `failed`/`DELIVERY_TARGET_UNAVAILABLE`；已完成的文件保留不变，用户重新连接并选择实时目标后可再次投递。

## 9. 安全与隐私

- 只有同时通过现有 session 认证和设备投递授权的请求可以读取目标；
- 目标 ID 与请求会话绑定，不允许跨设备或跨会话使用；
- 发往手机的网页元数据仅包含显示标题、支持站点域名和图标键，不包含完整 URL；
- 窗口和标签页标题仅用于当前内存响应，不写数据库、不写日志、不加入错误信息；
- 浏览器扩展与桌面端的通信端点只接受回环地址，并使用独立的扩展配对密钥；
- 扩展配对密钥由 CSPRNG 生成，桌面端仅保存哈希，不与手机 session token 共用；
- 扩展连接仅允许已发布的扩展 ID/来源，不允许通配 CORS；
- 粘贴前必须校验前台窗口身份；焦点不一致时宁可失败，不向未知窗口粘贴；
- 不向高完整性级别进程注入输入，不尝试绕过 UAC 或 Windows 前台窗口限制；
- 日志只记录脱敏的投递任务 ID、适配器 ID、状态和错误码。

## 10. UI 设计要求

### 10.1 电脑设置

新增“应用直达”设置区：

- 功能总开关；
- 隐私与行为说明；
- 已配对设备授权列表；
- 正式支持应用及健康状态；
- 浏览器扩展的未安装、已连接或异常状态；
- “投递前确认”开关，默认关闭；
- “实验性通用投递”开关，默认关闭。

### 10.2 手机端

- 设置中提供功能开关与权限状态说明；
- 仅当功能已启用且目标电脑具备能力时，发送页显示“发送到电脑应用”；
- 目标按电脑分组，显示图标、应用名、目标显示名、稳定/实验性和当前可用状态；
- 最近使用目标可排在前面，但已关闭目标不得自动替换成其他窗口；
- 传输记录分别展示“文件传输”和“应用投递”结果；
- 投递失败的已完成传输显示“重新投递”。

## 11. 测试与验收

### 11.1 自动化测试

- 权限：总开关、设备授权、会话身份和撤销覆盖；
- 隐私：未授权请求不返回目标，标题和 URL 不进入 DB/日志；
- 支持列表：默认只返回稳定适配器匹配目标，实验性开关行为可验证；
- 会话隔离：一台手机不能使用另一台手机的 `targetId`；
- 目标时效：窗口关闭、标签页关闭、服务重启和会话终止的失效测试；
- 状态独立：投递失败时传输仍为 `completed`；
- 重新投递：只新建 delivery job，不创建传输、不重传文件；
- 并发：多传输可并行，同一电脑的 delivery job 严格串行；
- 剪贴板：成功恢复原常见格式，失败保留待投递图片；
- 回归：不携带 `deliveryIntent` 的所有现有传输测试保持通过。

### 11.2 真机验收

1. 功能关闭时，现有配对、mDNS、M:N 传输和历史记录无变化；
2. 未授权手机无法获得任何应用或标签页信息；
3. 默认目标列表只显示已打开且可用的微信和 Gemini；
4. 单张和多张图片可进入微信当前会话输入区，不自动发送；
5. 单张和多张图片可进入手机选择的 Gemini 标签页，不自动提交；
6. 目标关闭、目标变化或用户切换前台窗口时，不向错误窗口粘贴；
7. 投递失败时文件仍已保存，图片仍可手动粘贴，且可免上传重新投递；
8. 投递成功后恢复原剪贴板的文本、HTML、图片或文件列表；
9. 两台手机同时完成文件传输时，投递按队列顺序执行，无剪贴板交叉或粘贴错窗口；
10. 扩展未安装或断开时不显示 Gemini 目标，并给出明确的电脑端安装/修复引导。

微信、Chrome、Edge 和 Gemini 需建立真机版本兼容矩阵。每个正式适配器只能在已验证版本上标记为稳定，不能仅以“已发送键盘事件”作为验收通过。

## 12. 建议实施边界

实施计划应拆分为可独立验收的里程碑：

1. 权限、能力、目标模型和空适配器；
2. Windows 剪贴板、前台校验、投递队列和状态机；
3. 微信正式适配器与真机验收；
4. Chrome/Edge 扩展连接和 Gemini 正式适配器；
5. 手机目标选择、状态展示和免上传重新投递；
6. 多机并发、剪贴板恢复、隐私与全量回归；
7. 实验性通用投递开关。

每个里程碑必须先用自动化测试定义行为，然后实现；正式适配器必须有真机验收记录。
